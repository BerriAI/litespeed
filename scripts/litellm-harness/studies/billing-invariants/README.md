# Billing token-bucket conservation candidate

**Unpromoted; serial comparison predeclared.** A preallocation amendment permits using only the existing safe budget headroom while retaining every unknown reservation. This four-attempt development comparison does not replace an interrupted study or grant additional budget.

## Evidence behind the change

Both completed Flash attempts on the larger billing task overcharge a synthetic mixed cached-audio/cache-creation request. At tool75 in repetition1 and tool89 in repetition2, the model adds a nested-split branch that bypasses the existing uncached budget. That old calculation visibly subtracts cache creation; the replacement text includes it. The information was available, but the interaction was missed. [Exact tool identities and edits](trace-observations.json), [public-path counterexample](../multi-module-development/public-path-observations.json).

The candidate adds one two-paragraph playbook to automatic initial navigation and explicit task-query navigation. It asks the solver to account for each token once, preserve the existing noncached-input budget, and exercise new modality handling together with nonzero cache writes. Missing versus explicit-zero rates, totals versus breakdown and existing pricing behavior remain named checks. The source anchors must exist, and the query must concern cached token/modality billing. This is learned training guidance, not an assertion that every checkout has this defect.

Tools, navigation ranking, final-review text, scheduling and the user task are unchanged. The control is current production code at public commit `f658678`; the candidate adds only this guide and its version marker, with two tests. Neither arm includes experimental grouped editing, chronological notices or query-navigation changes. [Candidate patch](candidate.patch), [reconstruction check](reconstruction.json).
